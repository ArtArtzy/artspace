# ARN SPACE Design System

เอกสารกลางสำหรับควบคุมภาพรวมของ ARN SPACE ให้ทุกหน้าใช้ภาษาเดียวกัน ทั้งสี ฟอนต์ ระยะห่าง พื้นผิว Card และพฤติกรรมของ Component

## หลักการออกแบบ

1. **อ่านง่ายก่อนตกแต่ง** — ตัวอักษรหลักต้องชัด มี contrast และไม่ลดขนาดเพื่อยัดข้อมูลให้แน่นเกินไป
2. **Dark literary space** — พื้นที่หลักเป็นโทน charcoal/forest green มี emerald เป็นสี action หลัก
3. **มี accent ตามประเภทเนื้อหา** — นิยาย แฟนฟิค และการ์ตูนมีสีประจำหมวด แต่ยังต้องใช้พื้นผิว ฟอนต์ และโครงสร้างร่วมกัน
4. **สม่ำเสมอข้ามหน้า** — Card, ปุ่ม, chip, Sidebar และระยะห่างควรเลือกจาก token เดียวกัน
5. **Interaction ต้องมองเห็นได้** — Hover, focus, active และ disabled ต้องแยกจากกันชัดเจน และใช้ `focus-visible` เสมอ

## Typography

ฟอนต์หลักของทุกหน้าใช้ **Prompt** ผ่าน `font-sans` และ `--font-prompt` เท่านั้น ห้ามเพิ่มฟอนต์ใหม่ในหน้าใดหน้าหนึ่งโดยไม่มีเหตุผลด้านภาษา/การเข้าถึง

| Role | Size | Weight | Line height | Tailwind alias |
| --- | ---: | ---: | ---: | --- |
| Display | 56px | 700 | 1.08 | `text-ds-display` |
| H1 | 40px | 700 | 1.15 | `text-ds-h1` |
| H2 | 24px | 600 | 1.25 | `text-ds-h2` |
| H3 | 18px | 600 | 1.3 | `text-ds-h3` |
| Body | 15px | 400 | 1.6 | `text-ds-body` |
| Body small | 13px | 400 | 1.5 | `text-ds-body-sm` |
| Meta | 12px | 400 | 1.35 | `text-ds-meta` |
| Caption | 11px | 400 | 1.35 | `text-ds-caption` |

กฎเพิ่มเติม:

- ห้ามใช้ตัวอักษรที่อ่านได้จริงต่ำกว่า `11px`; ข้อยกเว้น `10px` ใช้ได้เฉพาะ metadata ที่ไม่สำคัญหรือ label ขนาดเล็กมาก
- ข้อความภาษาไทยบนพื้นหลังเข้มควรใช้ `11px` ขึ้นไปเพื่อรักษาความชัดเจน
- ตัวอักษรใน logo, icon หรือ notification counter ที่ไม่ใช่เนื้อหา สามารถเล็กกว่า `10px` ได้เมื่อจำเป็นต่อขนาดของ component
- หัวข้อใช้ `600` หรือ `700` ตามลำดับชั้น ไม่ใช้ `800`/`900` โดยไม่จำเป็น
- Thai body text ต้องมี line-height อย่างน้อย `1.5`
- ใช้ `truncate`, `line-clamp` หรือ responsive layout แทนการลด font จนอ่านยาก

### ตัวอักษรส่วนข้อมูลของการ์ดหนังสือ

ใช้ฟอนต์ Prompt และคงขนาดตัวอักษรทุกความกว้างจอดังนี้

| ข้อมูล | ขนาด | น้ำหนัก |
| --- | ---: | ---: |
| ชื่อเรื่อง | `15px` | `500` |
| ชื่อผู้แต่ง | `15px` | `400` |
| จำนวนตอน ยอดวิว และยอดไลก์ | `13px` | `400` |

- ชื่อเรื่องใช้ `text-ds-body` และ line-height `1.6` แสดงสูงสุด 2 บรรทัด พร้อมสำรองพื้นที่ความสูง 2 บรรทัด
- ชื่อผู้แต่งใช้ `text-ds-body` และ line-height `1.6` ส่วนจำนวนตอน ยอดวิว และยอดไลก์ใช้ `text-ds-body-sm` และ line-height `1.5` ทั้งสองส่วนใช้สี `--arn-color-text-muted`
- จำนวนตอน ยอดวิว และยอดไลก์เรียงในบรรทัดเดียวกันเมื่อมีพื้นที่พอ พร้อมไอคอนและคำอธิบายสำหรับ screen reader รายละเอียดเพิ่มเติมอยู่ใน `docs/book-card-system.md`

## Shape, shadow และ layout

- Small radius: `6px` — ปุ่มและ control ขนาดเล็ก
- Medium radius: `8px` — Card, input, menu
- Large radius: `12px` — Hero/Section ที่ต้องการความนุ่มขึ้น
- Pill: `999px` — chip, filter, status badge
- Card shadow: `var(--arn-shadow-card)`
- Floating shadow: `var(--arn-shadow-floating)`
- Accent glow: `var(--arn-shadow-glow)`
- Desktop content max-width: `1400px`
- หน้าแรกสำหรับผู้ที่ยังไม่ได้เข้าสู่ระบบใช้ content max-width `1536px` ตามระดับ `2xl` โดย Header, Hero, Page banner, รายการเรื่อง, ชุมชน และ Footer จัดกึ่งกลางและใช้ขอบเขตความกว้างเดียวกัน
- Community content grid: content + sidebar โดยใช้ gap เฉพาะของหน้านั้น ไม่ดึง spacing จากหน้าอ่านมาใช้ตรง ๆ

## Responsive layout และ breakpoints

ใช้ breakpoint หลักร่วมกันทั้งเว็บไซต์ที่ `768px`, `1280px` และ `1536px` โดยวัดจากความกว้าง viewport หน่วย CSS px ค่าที่ใช้งานมาจาก Tailwind screens ซึ่งปัจจุบันใช้ค่าเริ่มต้นใน `tailwind.config.ts`

| ช่วง viewport | Tailwind | แนวทางจัดเลย์เอาต์ |
| --- | --- | --- |
| ต่ำกว่า `768px` | class พื้นฐาน | Mobile ใช้เนื้อหาคอลัมน์เดียว เมนูแบบย่อ และจัดปุ่มให้แตะได้สะดวก |
| `768px` ถึงต่ำกว่า `1280px` | `md:` | Tablet เพิ่มจำนวนคอลัมน์ตามพื้นที่ และวางข้อมูลรองต่อจากเนื้อหาหลัก |
| `1280px` ถึงต่ำกว่า `1536px` | `xl:` | Desktop ใช้เมนูเต็มและวาง Sidebar ข้างเนื้อหาเมื่อหน้านั้นมี Sidebar |
| ตั้งแต่ `1536px` | `2xl:` | Wide desktop จัดเนื้อหากึ่งกลาง จำกัดความกว้างสูงสุดตาม page shell โดยค่าทั่วไปเป็น `1400px` และหน้าแรกสำหรับผู้เยี่ยมชมเป็น `1536px` |

### การเขียน responsive

- ออกแบบการจัดวางและ hierarchy ของ desktop ให้ตรงกับหน้าที่ต้องการ แล้วเขียน CSS แบบ mobile-first โดยใช้ class พื้นฐานสำหรับจอเล็ก และเพิ่ม `md:`, `xl:`, `2xl:` ตามพื้นที่ที่มากขึ้น
- Prefix แต่ละระดับเริ่มทำงานที่ค่าขั้นต่ำและต่อเนื่องไปยังจอที่กว้างกว่า เช่น `md:` เริ่มที่ `768px` รวมถึงช่วง desktop จนกว่าจะมี class ระดับถัดไปเปลี่ยนค่า
- ใช้ `sm:` ที่ `640px` และ `lg:` ที่ `1024px` สำหรับปรับรายละเอียดของ component เมื่อเนื้อหาต้องการ เช่น จำนวนการ์ดหรือระยะห่าง โดยยึดสาม breakpoint หลักเป็นจุดเปลี่ยนโครงหน้าร่วมกัน
- ใช้ค่าเดียวกันใน CSS Modules เช่น `@media (min-width: 768px)`, `@media (min-width: 1280px)` และ `@media (min-width: 1536px)`
- ที่ `2xl` ปรับเฉพาะส่วนที่ได้ประโยชน์จากพื้นที่เพิ่ม ส่วนที่พอดีอยู่แล้วสามารถสืบทอดค่าจาก `xl` ได้
- หากเนื้อหาของ component ต้องเปลี่ยนที่ความกว้างอื่น ให้เลือกตามจุดที่เนื้อหาเริ่มเบียดกันและบันทึกเหตุผลไว้ใกล้กฎที่เกี่ยวข้อง

### พฤติกรรมของเนื้อหา

- Sidebar ข้างเนื้อหาเริ่มที่ `xl` (`1280px`) สำหรับหน้าที่มีข้อมูลรองข้างเนื้อหาหลัก ส่วนจอเล็กให้เรียงข้อมูลรองด้านล่างหรือใช้ส่วนพับเปิดได้ตามความเหมาะสม
- เมนูเต็มเริ่มที่ `xl` โดยช่วงต่ำกว่านั้นให้มีเมนูแบบย่อที่เข้าถึงปลายทางสำคัญได้ครบ
- เมนูหลักด้านบน (TopMenu) ใช้ตัวอักษรขนาด `15px` ที่ `xl` และ `18px` ที่ `2xl` ในทุกหน้าที่ใช้คอมโพเนนต์นี้ หน้าแรกก่อนเข้าสู่ระบบเว้นระยะระหว่างรายการเมนู `12px` ที่ `2xl`
- จำนวนคอลัมน์ของ Book Card ปรับตามความกว้างพื้นที่จริง โดยเริ่มจาก 2–3 คอลัมน์บนมือถือ และเพิ่มขึ้นเมื่อชื่อเรื่อง ปก และ metadata ยังอ่านได้สะดวก
- หน้าแรกเรียงแบนเนอร์ ตามด้วย “กำลังมาแรง”, “Top 20 ยอดนิยม” จำนวน 20 เรื่อง, “สำรวจเพิ่มเติม”, “เรื่องใหม่”, “เรื่องจบแล้ว”, “อัปเดตล่าสุด”, “อ่านล่าสุด” และ “นักเขียนแนะนำ” ทุกขนาดจอ หลังเข้าสู่ระบบเพิ่ม “อ่านต่อ” กับ “สำหรับคุณ” ระหว่างแบนเนอร์และ “กำลังมาแรง”
- บนหน้าแรกที่จอกว้างต่ำกว่า `xl` แถวเรื่องเลื่อนแนวนอนได้ โดยเหลือพื้นที่ให้เห็นส่วนหนึ่งของการ์ดถัดไป
- หมวดแนะนำใน “สำรวจเพิ่มเติม” เลื่อนแนวนอนบนจอที่กว้างต่ำกว่า `768px` ช่วงแท็บเล็ต `768–1279px` แสดงครบ 12 หมวดเป็นกริด 4 คอลัมน์ 3 แถวในแต่ละแท็บ (นิยาย แฟนฟิค และการ์ตูน)
- หมวด “เรื่องใหม่ น่าจับตา” และ “เรื่องจบแล้ว อ่านยาวได้เลย” แสดงหมวดละ 8 เรื่องเมื่อจอกว้างต่ำกว่า `xl` ส่วนที่ `xl` แสดง 2 แถว แถวละ 7 เรื่อง และที่ `2xl` แสดง 2 แถว แถวละ 8 เรื่อง
- รายการหนังสือทั้งสามหมวดบนหน้าแรกก่อนเข้าสู่ระบบคัดนิยายประมาณ 50% แฟนฟิค 25% และการ์ตูน 25% แล้วเรียง Top 20 ตามยอดอ่าน
- กริดหนังสือหน้าแรกใช้ 7 เรื่องต่อแถวที่ `xl` และ 8 เรื่องต่อแถวที่ `2xl` ทั้งก่อนและหลังเข้าสู่ระบบ Top 20 มี 20 เรื่องตามอันดับ
- หน้านิยาย แฟนฟิค และการ์ตูนใช้พื้นที่รายการเรื่องเต็มแนวเนื้อหา แถวแนะนำเลื่อนแนวนอนเมื่อจอกว้างต่ำกว่า `xl` ส่วนกริดเดสก์ท็อปใช้ 7 เรื่องต่อแถวที่ `xl` และ 8 เรื่องต่อแถวที่ `2xl` เช่นเดียวกับหน้าแรก
- ส่วน “นักเขียนแนะนำ” บนหน้าแรกใช้เลย์เอาต์เดียวกันก่อนและหลังเข้าสู่ระบบ บนจอที่กว้างต่ำกว่า `768px` เลื่อนแนวนอนได้ ช่วง `768–1023px` แสดง 8 คนใน 2 แถว แถวละ 4 คน ตั้งแต่ `1024px` แสดง 12 คนใน 2 แถว แถวละ 6 คน
- Footer บนแท็บเล็ต `768–1279px` วางโลโก้เหนือกริดลิงก์ 3 คอลัมน์ แสดงลิงก์ทุกหมวด และจัดไอคอนโซเชียลกับข้อความลิขสิทธิ์กึ่งกลางใต้เส้นคั่น บนมือถือพับกลุ่มลิงก์ไว้เมื่อเริ่มต้นและเปิดได้ครั้งละหนึ่งกลุ่ม
- ลดระยะห่างและจำนวนคอลัมน์ก่อนลดขนาดตัวอักษร โดยรักษาขนาดตัวอักษรขั้นต่ำและ line-height ตาม Typography
- ให้ปุ่มและลิงก์หลักมีพื้นที่กดอย่างน้อย `44 × 44px` และรักษา focus-visible สำหรับการใช้คีย์บอร์ด
- ใช้ `min-w-0`, การตัดบรรทัด และ overflow ภายใน component เพื่อให้เนื้อหาอยู่ใน viewport ตารางหรือแถบเมนูยาวสามารถเลื่อนแนวนอนภายในพื้นที่ของตัวเองได้
- หน้าที่รองรับ responsive ต้องเข้าถึงเนื้อหาและปุ่มได้ทุกช่วงจอ ใช้ `DesktopOnlyNotice` เฉพาะหน้าที่ยังรองรับเดสก์ท็อปเท่านั้น
- เงื่อนไขการแสดงเนื้อหาตามสถานะเข้าสู่ระบบใช้ร่วมกันทุกขนาดจอ เช่น Sidebar ที่ซ่อนสำหรับผู้เยี่ยมชมต้องซ่อนทั้งบนมือถือและ desktop

### การตรวจสอบก่อนส่งงาน

- ตรวจที่ความกว้าง `360`, `390`, `768`, `1280`, `1536` และ `1920px` พร้อมลองจอแคบ `320px`
- ตรวจรอยต่อที่ `767/768px`, `1279/1280px` และ `1535/1536px` และลองย่อขยายต่อเนื่องระหว่างช่วง
- ตรวจเมนู ฟอร์ม ปุ่มหลัก ลิงก์ Sidebar และการเลื่อนหน้า รวมถึงสถานะก่อนและหลังเข้าสู่ระบบเมื่อเกี่ยวข้อง
- ตรวจว่าที่จอกว้างเนื้อหาจัดกึ่งกลางและความกว้างสูงสุดตรงกับ page shell โดยหน้าทั่วไปใช้ `1400px` และหน้าแรกสำหรับผู้เยี่ยมชมใช้ `1536px`

## Primitive classes

### แบนเนอร์หน้าแรก

- แสดง 5 สไลด์ โดยเป็นเรื่องแฟนตาซี Boy Love และ Girl Love อย่างละ 1 เรื่อง พร้อมกิจกรรม Writing Challenge และ Readathon
- ทั้งภาพและข้อความของแต่ละแบนเนอร์เป็นลิงก์ไปยังหน้ารายละเอียดเรื่องหรือกิจกรรมนั้น
- แบนเนอร์ทั้ง 5 ภาพมี CTA ใต้คำโปรยทุกขนาดจอ ทั้งก่อนและหลังเข้าสู่ระบบ ใช้กรอบภาพตามธีมของแต่ละแบนเนอร์และแสดง “อ่านเรื่องนี้” หรือ “ดูกิจกรรม” เป็นข้อความของลิงก์ที่เข้าถึงได้
- ภาพ PC ใช้ขนาด `1536 × 512px` ตั้งแต่ `1280px` ภาพ Tablet ใช้ `1024 × 512px` ในช่วง `768–1279px` และภาพ Mobile ใช้ `768 × 960px` สำหรับช่วงต่ำกว่า `768px`
- ใช้ภาพที่จัดองค์ประกอบแยกตามอุปกรณ์ผ่าน `<picture>` และ `getImageProps` โดยใส่ชื่อเรื่อง หมวด และคำโปรยลงในภาพโดยตรง พร้อมออกแบบตัวอักษรให้เข้ากับบรรยากาศแฟนตาซีหรือโรแมนติกของแต่ละชุด
- จัดวางข้อความสำหรับ PC และ Tablet ทางซ้าย ส่วน Mobile ใช้พื้นที่ด้านล่างของภาพ พร้อมเว้นพื้นที่สำหรับปุ่มควบคุมสไลด์ และใส่ alt text กับหัวข้อสำหรับ screen reader
- การเลือกสไลด์ ปุ่มก่อนหน้า ปุ่มถัดไป และปุ่มหยุดการเลื่อนอัตโนมัติมีพื้นที่กดอย่างน้อย `44 × 44px` พร้อม focus-visible
- การเลื่อนอัตโนมัติหยุดเมื่อชี้เมาส์ ใช้คีย์บอร์ดอยู่ภายในแบนเนอร์ หรือเปิด prefers-reduced-motion
- Hero หน้านิยาย แฟนฟิค และการ์ตูนใช้สัดส่วน ความกว้างสูงสุดตามสถานะเข้าสู่ระบบ และตัวควบคุมเดียวกับหน้าแรก ชื่อเรื่องใช้ตัวอักษรที่ออกแบบเฉพาะให้เข้ากับงานภาพของแต่ละเรื่อง หมวด คำโปรย และชื่อผู้เขียนอยู่ในภาพ พร้อมข้อความสำหรับ screen reader และ CTA ที่กดได้

ใช้ class กลางก่อนสร้าง utility ใหม่:

```tsx
<section className="ds-card p-ds-4">...</section>
<section className="ds-section p-ds-4">...</section>
<div className="ds-page-banner-shell"><div className="ds-page-banner">...</div></div>
<button className="ds-button-primary px-ds-4">บันทึก</button>
<button className="ds-button-secondary px-ds-4">ยกเลิก</button>
<span className="ds-chip px-ds-3">แฟนตาซี</span>
```

Class เหล่านี้อยู่ใน `app/globals.css` และ Tailwind aliases อยู่ใน `tailwind.config.ts` โดย `.ds-card` ใช้กับ Card ทั่วไป, `.ds-section` ใช้กับ Section ที่มี heading/list ภายใน และ `.ds-input` ใช้กับช่องค้นหา/ฟอร์ม

### Community content surface

คอนเทนต์หลักฝั่งซ้ายของหน้าชุมชนใช้ wrapper `.ds-community-content` เพื่อให้ Card/Section ใช้พื้น `--arn-color-canvas` แบบเดียวกับหน้าการอ่านและไม่กลายเป็นพื้นเขียวทั้งแผง ส่วนสีเขียวของชุมชนยังใช้ได้กับ active state, badge, status และ CTA ตามความหมายของ UI

### Sticky page title banner

ใช้ `.ds-page-banner-shell` ครอบ `.ds-page-banner` สำหรับ Page Identity Bar ที่อยู่ระหว่าง Hero Banner และ Sub Menu โดยใช้พื้นผิวร่วมของระบบ และเติมสีประจำหน้าบาง ๆ เท่านั้น ไม่ใช้ glow หรือ gradient ที่เด่นจนกลายเป็นอีก Card หนึ่ง

- คอมโพเนนต์กลางอยู่ที่ `components/PageTitleBar.tsx` และรองรับ `home`, `novel`, `fanfic`, `cartoon`, `community`
- สีประจำหน้าใช้กับ icon, title, border และ tint ของ Identity Bar เท่านั้น ไม่เปลี่ยนสี CTA, header, notification, profile หรือ success state
- Sub Menu ที่อยู่ถัดลงมาเป็น navigation แยกต่างหาก พื้นหลังยังคงเป็น neutral dark และใช้ accent เฉพาะ active indicator ได้
- เมื่อมี banner สูงประมาณ 60px ให้แถบ filter/menu ถัดไปใช้ offset `top-[142px]` เพื่อไม่ทับกัน

## Accessibility baseline

- ทุกปุ่มต้องเป็น `<button>` และทุก navigation/action ที่พาไป URL ต้องเป็น `<Link>`
- Icon ที่ไม่มีความหมายสำหรับ screen reader ใช้ `aria-hidden="true"`
- Interactive element ต้องมี `focus-visible` ring
- ปุ่ม disabled ต้องยังเห็นได้ว่า disabled และห้ามใช้สีเดียวกับ active
- รูปภาพ content ต้องมี alt ที่บอกสิ่งสำคัญของรูป; รูปตกแต่งใช้ alt ว่างได้
- อย่าใช้สีเป็นตัวบอกสถานะเพียงอย่างเดียว ให้มีข้อความหรือ icon ร่วมด้วย
